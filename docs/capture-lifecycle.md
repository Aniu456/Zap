# 截图生命周期

截图流程分为四个职责，不由多个布尔标志共同决定是否活跃：

- `CaptureController`：连接权限、快捷键、剪贴板、置顶窗口和错误提示。
- `CaptureCoordinator`：唯一的请求状态与所有权；状态为 idle、acquiring(requestID)、presenting(requestID)。拥有采集 Task 和当前会话。
- `ScreenGrabber`：获取一组完整的屏幕快照。负责取消检查、备用采集和显示器布局一致性，不创建窗口。
- `CaptureSession`：选区、标注和导出。通过 `CaptureWindowGroup` 管理展示；后者独占这一组窗口和鼠标监听器。

## 生命周期约束

1. `begin()` 在已有请求或会话时不重复启动；快捷键 `toggle()` 仍允许再次按下取消。
2. 取消先把协调器设为空闲，再取消 Task、关闭会话。即使关闭同步触发完成回调，也不能重复处理结果。
3. 采集结果、错误和会话完成回调都校验请求身份。已经取消的请求不能打开窗口、显示错误或清理后续会话。
4. 系统采集 API 不一定能立刻中止，但取消会阻止后续备用采集和结果展示。
5. 所有显示器采集完成、尺寸和布局校验通过后才创建会话。任一显示器失败或采集期间布局变化则整体失败，不显示半套遮罩。
6. 先创建所有窗口并准备画面；下一主线程事件周期再统一显示、设置键盘焦点和安装鼠标监听，且关闭后的展示请求无效。
7. 退出时立即隐藏窗口、移除监听器，下一事件周期只释放这一组窗口的视图。旧窗口清理不会触碰新会话。
8. 会话完成只通知一次；关闭后的鼠标和键盘输入不再处理。

## 验证

`CaptureLifecycleTests` 通过可控的异步采集和展示替身验证重复启动、取消、过期结果、过期错误、重复结束回调、权限失败、空结果。真实 AppKit 窗口测试覆盖展示前取消、旧窗口清理与新会话隔离、Esc 退出。`CaptureOverlayInputTests` 在展示事件完成后发送第一组鼠标拖动事件。

仍需在正式安装包上验收：快捷键/菜单首次启动、快速取消后重新启动、普通桌面与全屏应用、多显示器不同缩放、截图过程中显示器连接变化、标注/复制/保存/置顶。自动化测试不能证明先前偶发闪屏的唯一根因，也不能替代实际多显示器与 Spaces 验收。
